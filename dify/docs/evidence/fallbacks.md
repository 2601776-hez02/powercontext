# 最坏情况下的回答（自动生成）

> 判题方可能遇到三种"不顺"：没配模型、模型名不对、后端连不上。
> 这份记录说明每种情况下**玩家仍然能看到什么**。

## 1) 模型不可用（没配 / 名字不对）

两段剧本节点都设了 `error_strategy = default-value`，兜底文案非空：

| 节点 | error_strategy | 兜底文案长度 |
| --- | --- | --- |
| `llm_narrate`（写正文） | default-value | 30 字 |
| `llm_mind`（写读心） | default-value | 18 字 |

所以即使模型完全不可用，Answer 节点仍然拼出：

```
【第 N 回合 · 判定：成功】阿箬收下 3 个铜板，把桂花酿推到你面前。
【阿箬的杯边话】…
> 铜板 17｜风评 2｜被记账 0｜大堂
灯芯跳了一下，堂里静了片刻——这一回合的判定都在上面的方括号里。
```

**判定行与数字来自引擎，不依赖模型**；模型只负责最后那句小说。

> 自检第 44 条守着这一点：两个节点必须同时满足「default-value」与「兜底文案非空」。

## 2) 后端连不上

HTTP 节点没有（也无法有）兜底——Dify 在节点执行前就会失败。
所以默认 DSL 直接连**公网演示后端**，并把超时放宽到 connect 10s / read 60s：

* 默认：`dsl/wangchuan-tavern.chatflow.yaml` → 公网地址（导入即可跑）
* 完全本地：`dsl/wangchuan-tavern.local.yaml` → `http://172.17.0.1:9100`

容器内的连通性实测见 [`connectivity.md`](connectivity.md)。

## 3) 一句没用的话（「测试」「1」「演示一下」）

不会被当成「打量」丢掉，而是给出：店名 + 三条规矩 + 一句「先要一壶桂花酿试试」。
见 `engine/game.py` 里 `_bare` 那段与 `_ask_answer` 的「演示」分支。
