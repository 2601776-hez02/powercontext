真实痛点

不是没有资料，是资料「在，但找不回来」

下面三件事每天都在发生，知序分别用三种机制回应，而不是再加一个聊天框。

01

查资料靠记忆

只记得大概意思，记不住文件名；中文译名和英文缩写混着写，搜「召回」搜不到「recall」。

→ 双通道混合检索：ngram 全文索引保证词对得上，HNSW 向量索引负责「换个说法也能靠近」，术语表补同义词，RRF 融合两路排序。

02

结论没有出处

写文档时引用一句「efSearch 影响召回」，却指不回第几段第几行，评审一问就卡住。

→ 字符级引用：入库时算好路径、小节、行号、字符区间；检索结果与证据包都带 citation，原文[start:end] 可逐条校验。

03

周报重复整理

每周五翻聊天记录、对进度、找实验结果，重新组织一遍，还经常漏掉上周的风险。

→ 事件流折叠：任务状态变更写事件，资料入库带时间戳，检索留日志；周报用 SQL 按周期聚合，一条命令生成并归档。

片段表 DDL（片段内建双索引）

      
CREATE TABLE zx_chunks (
  id BIGINT NOT NULL AUTO_INCREMENT,
  document_id BIGINT NOT NULL,
  heading VARCHAR(255) NOT NULL,
  body TEXT NOT NULL,
  char_start INT NOT NULL, char_end INT NOT NULL,
  start_line INT NOT NULL, end_line INT NOT NULL,
  embedding VECTOR(384) NOT NULL,
  FULLTEXT KEY ft_body (body) WITH PARSER ngram,
  VECTOR KEY vk_embedding (embedding)
    WITH (DISTANCE=COSINE, TYPE=HNSW),
  PRIMARY KEY (id)
) DEFAULT CHARSET = utf8mb4;

      本地运行
      
    
      三条命令，从零到可检索
      
    
      需要 Python 3.11+；seekdb 以轮子形式随依赖安装，不需要 Docker 或独立数据库服务。
      
  
      
  
      
    
      
      
      1
      安装依赖
      pip install -r requirements.txt
      
      
      2
      初始化并入库
      python run.py init
      
      
      3
      检索 / 证据包
      python run.py ask "HNSW 的 efSearch 怎么影响召回率"
      
      
      4
      本地工作台（可选）
      python run.py serve   # http://127.0.0.1:8765
      
    
      
    
      
      
      运行说明
      
      
        
        
      • 数据目录：默认 .zhixu/，可用 ZHIXU_DATA_DIR 指到大容量磁盘。
        • 
        
      • 零安装入口：python run.py <命令> 直接使用仓库里的 src/；也可 pip install -e . 后用 zhixu 命令。
        • 
        
      • 单进程窗口：嵌入式 seekdb 独占数据目录，serve 与写命令不要同时跑。
        • 
        
      • 幂等：建表用 IF NOT EXISTS，入库按内容哈希；重复执行不会重复写入。
        • 
        
      • 离线：向量化是本地字符 n-gram 哈希，不调用任何模型或外部 API。
        • 
        
      • 可信边界：同义改写靠术语表兜底，真正的语义泛化需要换外部 embedding，文档里不夸大。
        •
