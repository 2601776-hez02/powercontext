# 阅读笔记：余弦距离、L2 距离与向量归一化

## 三种距离

- **L2（欧氏）距离**：`sqrt(Σ(a-b)²)`，衡量绝对位置差异，受向量长度影响。
- **内积**：`Σ a·b`，长度越大分数越大，适合「越大越相关」的排序。
- **余弦距离**：`1 - (a·b)/(|a||b|)`，只看方向不看长度，取值 0～2。

如果向量已经 L2 归一化，那么余弦相似度等于内积，L2 距离与余弦距离单调对应：`L2² = 2 - 2·cos`。所以「用哪种距离」在归一化之后差别不大，关键是建表和查询时保持一致。

## 建表时的选择

```sql
VECTOR KEY vk_embedding (embedding) WITH (DISTANCE=COSINE, TYPE=HNSW)
```

距离度量写在索引定义里，查询时用对应的距离函数并加 `APPROXIMATE` 走索引：

```sql
SELECT id, cosine_distance(embedding, :q) AS d
FROM zx_chunks
ORDER BY cosine_distance(embedding, :q) APPROXIMATE
LIMIT 20;
```

如果不加 `APPROXIMATE`，优化器可能退化成全表扫描 + 排序：数据量小的时候看不出差别，数据量一大就会慢得离谱。这也是排查「为什么向量检索没走索引」的第一检查点。

## 归一化的坑

- 零向量：归一化会除零，必须兜底（例如给一个默认方向）。
- 归一化之后，向量元素在 `[-1, 1]`，序列化成字面量时保留 6 位小数足够，太长会放大字符串体积。
- 不同模型产出的向量不能混用：维度不同、归一化方式不同，距离都不可比。

## 和评测的关系

距离是手段，不是指标。真正要报的是「证据召回率」和「延迟」，距离只用来排序和设阈值。阈值不要拍死，用「相对最佳结果的比例」更稳：例如只保留相似度不低于最佳值 55% 的候选。
