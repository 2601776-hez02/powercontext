# 需求：一屏内回答「这条结论出自哪里」

## 用户故事

作为要写综述和方案的学生/工程师，我希望输入一句自然语言，就能拿到若干条**原文片段**，每条都标明来自哪篇资料、哪个小节、第几行到第几行、字符区间是多少，这样我可以直接把引用贴进文档，而不必再打开原文件核对。

## 功能需求

1. **资料导入**：支持 Markdown 目录批量导入；同一篇资料重复导入不产生重复数据，内容变化时整体替换该资料的片段。
2. **检索**：同时支持关键词（全文）与语义近似（向量）两条通道，结果融合排序；中文、英文、中英混写都能命中。
3. **出处**：每条结果必须能回查原文——文件路径、小节标题、行号区间、字符区间四者齐全，且 `原文[字符起点:字符终点]` 必须与展示片段一致。
4. **证据包**：把若干条证据拼成一段可直接交给模型的上下文，受 UTF-8 字节预算约束，预算包含信封、JSON、引用和正文，超出就少放一条，而不是截断半句话。
5. **任务与周报**：任务有状态、优先级、截止日期；状态变化写事件；周报按事件自动汇总。
6. **本地优先**：所有数据落在本机数据库，不依赖外部服务。

## 非功能需求

- 首次初始化可重复执行，不因「表已存在」失败。
- 进程重启后数据完整可读，片段数量、任务事件不丢。
- 单次检索在百级片段规模下应在 50 ms 量级完成。
- 只依赖 Python 标准库与 seekdb 客户端，避免复杂的服务依赖。

## 验收口径

- 用一句包含专有名词的问题检索，Top3 中至少两条来自相关小节。
- 任取一条结果，按行号打开原文，片段能在对应行找到。
- 预算 1800 字节时，证据包实际字节数不超过 1800，且至少包含一条证据。
