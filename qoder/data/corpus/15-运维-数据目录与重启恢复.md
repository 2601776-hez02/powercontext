# 运维笔记：数据目录、重启恢复与幂等初始化

## 数据放在哪

默认在项目根目录的 `.zhixu/` 下，里面是 seekdb 的嵌入式数据目录，另有 `reports/` 存放自动生成的周报。可以用环境变量 `ZHIXU_DATA_DIR` 指到别的盘，方便备份和迁移。

`.zhixu/` 已加入 `.gitignore`：**资料正文和任务数据不进代码仓库**，仓库里只保留语料和种子文件。

## 启动过程

`pylibseekdb.open(path)` 启动嵌入式实例并返回连接参数（随机端口），随后用 PyMySQL 连 `test` 库。每次命令都是「打开 → 操作 → 关闭」，服务模式则在整个进程生命周期内持有一个实例。

## 幂等初始化

建表全部使用 `CREATE TABLE IF NOT EXISTS`，重复执行不会报「表已存在」。入库按内容哈希判断：

- 文件内容没变 → 跳过，片段数不变；
- 文件内容变了 → 删除该文档旧片段，重新切分写入，文档 id 保持不变；
- 强制重建 → `python -m zhixu init --rebuild`。

这样「重复运行初始化」是安全的，也不会出现「重复创建集合导致首次运行失败」的问题。

## 重启验证

1. 记录重启前的片段数、任务数、事件数；
2. `Ctrl+C` 停掉服务，重新 `python -m zhixu doctor`；
3. 三个数字必须一致，且演示检索仍能命中。

## 单进程窗口

嵌入式 seekdb 在一个进程内独占数据目录。**不要同时**在终端跑 `zhixu` 写命令和 `zhixu serve`，否则第二个进程可能拿不到实例。约定是：需要写数据时先停服务，或者统一通过 Web API 写。

## 备份与迁移

整个 `.zhixu/` 目录拷贝即可完成迁移；恢复时把目录放回原位，`doctor` 通过就说明数据可用。周报是派生数据，丢了可以重新生成，不需要单独备份。
