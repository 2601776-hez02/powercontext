# 评测规范：证据召回率、字节预算与引用核对

## 评测目标

不是评「回答写得好不好」，而是评「证据找得准不准、拼得下不下得去」。所有指标都可以离线计算，不调用模型。

## 指标一：证据召回率

对每条查询准备 gold 证据区间（来自人工标注：哪篇资料的哪一段是真正回答问题的）。把系统返回的字符区间按文档合并，计算：

- 词项集合：对已选原文和 gold 原文分别做小写化，用 `[a-z]+|\d+` 提取英文与数字，中文按二元组补齐；
- 词项召回 = |已选 ∩ gold| / |gold|，按词频多重集合求交集；
- 对 N 条查询取算术平均。

目标：48 条查询平均证据词项召回 ≥ 0.65。

## 指标二：完整证据比例

要求合并后的区间**覆盖 gold 的全部字符区间**，允许由多个片段共同完成。完整查询数 / 总查询数 ≥ 40%。

## 指标三：字节预算

`content_bytes` 必须等于完整输出的 UTF-8 字节数，并且小于等于 `max_bytes`。预算包含：信封标记（`BEGIN_...` / `END_...`）、JSON 结构、引用字段、正文。**不能只算正文长度**——中文一个字 3 字节，JSON 的 key 和引号同样占预算，忽略它们就会超限。

边界情况：

- 预算很小（比如 512 字节）时，允许返回更少的证据，但不允许超预算；
- 没有可用证据时返回空 Context，而不是塞入不相关的内容；
- 同一片段重复出现要去重，不能靠重复内容凑满预算。

## 指标四：引用可回查

逐条检查：

1. `path` 指向的资料存在；
2. `char_start < char_end <= len(原文)`；
3. `原文[char_start:char_end] == 片段正文`；
4. 行号区间与字符区间一致。

任何一条不满足，该条证据判失败。

## 记录方式

每次评测把配置（分块、efSearch、术语表版本）、指标和失败样例写进实验记录，周报里只引用结论和链接，不复制表格，避免两份数据不一致。
