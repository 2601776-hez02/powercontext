# 模型量化：INT8 与 FP16 的体积与质量

端侧部署的第一个约束是体积。以 bge-small-zh-v1.5 的 ONNX 产物为例，同一套权重有三种常见精度：

| 精度 | 文件 | 体积 |
| --- | --- | --- |
| FP32 | `onnx/model.onnx` | 90.46 MB |
| FP16 | `onnx/model_fp16.onnx` | 45.30 MB |
| INT8 | `onnx/model_quantized.onnx` | 22.90 MB |

按“量化前体积 / 量化后体积”计算，INT8 的压缩比约为 3.95 倍，FP16 约为 2.0 倍。

INT8 通常采用动态量化：权重离线量化为 int8，激活值在推理时按 batch 统计动态缩放，因此不需要校准数据集，也不会显著改变模型结构。代价是数值精度下降，长尾语义的区分度可能变弱。

量化并不等于“白拿”：必须用同一份评测集、同一套查询，对比量化前后的检索质量（Recall@5、nDCG@5 等），并记录下降幅度。如果质量下降超过可接受范围，就应该换更大的模型或更保守的精度，而不是继续压缩。

实践结论是：INT8 在 512 维中文 embedding 上通常只带来很小的质量损失，但把模型下载量从 90 MB 降到 23 MB，对首屏体验的影响是数量级的。
