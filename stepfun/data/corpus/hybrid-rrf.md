# 混合检索与 RRF 融合

单一检索各有盲区：向量检索擅长语义相近但可能漏掉精确术语，全文检索擅长精确词面但不懂同义改写。混合检索把两路候选合并排序，通常能同时提高召回与准确率。

工程上最常用的融合算法是 RRF（Reciprocal Rank Fusion，倒数排名融合）：

```
score(doc) = Σ_i  1 / (k + rank_i(doc))
```

其中 `rank_i(doc)` 是该文档在第 i 路检索结果里的名次（从 1 开始），`k` 是平滑常数，常用取值 60。k 越大，排名靠后的文档权重越接近，融合越“平”；k 越小，头部结果越强势。

`rank_window_size` 控制每一路各取多少候选进入融合：窗口太小会漏掉好结果，窗口太大则融合成本上升。经验值是 40 到 100。

在 seekdb 里，混合检索由 `DBMS_HYBRID_SEARCH` 在数据库内部完成：先由 `GET_SQL` 依据传入的参数（全文查询、向量查询、RRF 配置、返回条数）生成一条 SQL，再执行这条 SQL。也就是说全文候选、向量候选和 RRF 排序都在数据库里发生，应用层拿到的已经是融合好的结果，不需要先查两路再自己拼。
