# 评测方法：Recall@K、nDCG 与计时口径

没有评测就没有优化。检索质量的常用指标：

- **Recall@K**：前 K 条结果里是否包含金标文档。单金标时它就是 0/1，多查询取平均后得到整体召回率。它简单、可解释，适合端侧小知识库。
- **nDCG@K**：考虑名次的折损，命中越靠前分数越高，适合多金标与分级相关性。
- **MRR**：第一个金标出现位置的倒数，衡量“第一条就答对”的能力。

工程上还要固定计时口径：

1. 记录设备、浏览器版本、模型版本、精度、推理后端、批大小、seekdb 版本与索引参数；
2. 分阶段计时：模型下载、模型加载、文档向量化、写入、索引刷新、查询向量化、数据库检索、端到端；
3. 首次请求与预热后分开报告，不能把冷启动混进稳定态；
4. 每个配置重复多轮，报告中位数与 P95，而不是只挑最快的一次；
5. WebGPU 与 WASM 两条路径都要各测一遍，并说明降级是否影响功能。

只有把“质量”和“性能”放在同一张表里对比，量化前后的取舍才是可复现的结论，而不是主观感受。
