# HNSW 向量索引与参数选择

HNSW（Hierarchical Navigable Small World）是目前最常用的近似最近邻索引。它把向量组织成多层可导航的小世界图：上层稀疏，用于快速跨区域跳转；底层稠密，用于精细收敛。查询从最上层入口点开始，逐层贪心地向距离更近的邻居移动，到最底层时得到候选集合。

关键参数：

- `m`：每个节点的邻居数，常见取值 16。m 越大，图越稠密，召回越高，构建与内存开销也越大。
- `ef_construction`：建图时的候选队列长度，常见取值 200。它只影响构建质量，不影响查询耗时。
- `ef_search`：查询时的候选队列长度。它直接决定查询的召回与延迟，是唯一可以在线调整的旋钮。

在 512 维、余弦距离的语料上，HNSW 的查询通常能把候选集合从全表的 N 条压缩到几十条，再精算距离，因此单次检索可以稳定在毫秒级。要注意近似索引和写入之间存在时间差：新写入的向量在索引刷新之前可能查不到，所以工程上要么在写入后调用一次索引刷新，要么接受短暂延迟并把它写进产品说明。
