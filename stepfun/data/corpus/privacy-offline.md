# 隐私与离线：为什么要把推理放在端侧

把文档向量化放在浏览器里，最直接的好处是数据不出设备。用户导入的笔记、财报、病历、合同，如果先上传到服务端再向量化，就等于把原始文本交给了一个不信任的第三方；即使是加密传输，服务端仍然能看到明文。

端侧推理的第二个好处是可用性：模型文件随应用一起分发并缓存在本地，断网时仍然能导入、检索；不依赖任何云端 API 的配额、密钥和计费。

代价也很明确：

- 首次使用要下载模型（INT8 之后约 23 MB，仍需要一次网络往返，或用安装包带上）；
- 低端设备上推理慢，需要 WASM 兜底与合理的批大小；
- 模型版本与精度必须由前端自己管理，不能指望服务端统一升级。

因此在架构上要把“推理”和“存储”彻底分开：浏览器负责分词、前向计算、池化归一化；服务端只接收向量与正文，做写入和检索。这样即使服务端被攻破，也拿不到用户没有提交的数据；反过来，服务端换数据库也不影响端侧模型。

判断一个“端侧”方案是否真的端侧，有三条检查线：模型文件是否本地加载、推理是否发生在本机、有没有把原文发给远端模型 API。
