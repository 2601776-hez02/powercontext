# WebGPU 与 WASM 两种推理后端

ONNX Runtime Web 提供多种执行后端，实际可用的是两类：

- **WebGPU**：把算子编译成 GPU 着色器在显卡上执行，适合大 batch 与卷积/矩阵乘密集的模型。首次运行需要编译管线，存在明显的预热开销；之后单次推理吞吐通常远高于 CPU。
- **WASM**：把 ORT 编译成 WebAssembly，在 CPU 上用 SIMD 与多线程执行。兼容性最好，几乎所有现代浏览器都可用；成本是吞吐受 CPU 核数限制。

一个面向真实用户的端侧应用不能假设 WebGPU 一定存在：旧显卡、虚拟机、部分 Linux 发行版、远程桌面环境都可能拿不到适配器。正确做法是：

1. 先探测 `navigator.gpu` 是否存在，并 `requestAdapter()` 拿到适配器；
2. 存在就按 WebGPU 初始化，失败时捕获异常；
3. 捕获到异常或探测失败，退回 WASM，并在界面上明确提示“当前后端为 WASM”；
4. 两条路径都必须能走完“导入 → 向量化 → 写入 → 检索”的全流程。

判断标准不是“我的机器上能跑”，而是“用户机器上最差也能跑”。
